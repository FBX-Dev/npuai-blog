过去两年，AI 行业有个默认假设：**模型能力越强，单位价格越低。**

2026 年这个方向反了。

摩根士丹利统计了字节跳动、阿里巴巴、百度、腾讯、MiniMax、智谱、月之暗面、DeepSeek 等厂商的官方报价，结论是：**2026 年第二季度，中国大模型平均 API 输入价格升至每百万 token 4.9 元，输出价格升至 21.9 元**；而 2025 年第一季度这两个数字分别是 3.3 元和 12.2 元——**涨幅约 48% 和 80%**。

## 涨价是怎么落地的

具体的调价动作，可以看出几种不同的思路。

**按月订阅的 Token Plan。** 6 月 MiniMax 发布 M3 的 API 后，把计费从按次改为按 token，Token Plan 分三档：Plus 49 / Max 119 / Ultra 469 元/月。7 月月之暗面发布 Kimi K3，API 输入（缓存未命中）20 元、输出 100 元/百万 token，同时面向 C 端推出五档会员（49 / 99 / 199 / 699 元/月）。阿里通义千问则按场景分层，提供按量即时计费、Token Plan 包月、Coding Plan 专属编程订阅三套方案。

**峰谷计价。** DeepSeek 新版 API 没采用月订阅，而是按缓存未命中输入、输出、缓存命中三类 token 定价。8 月 17 日调价引入峰谷机制：高峰时段为北京时间 9:00–12:00、14:00–18:00 共 7 小时，其余 17 小时按空闲价。8 月 23 日又优化规则，周末全天不再区分峰谷。

涨价幅度不小：**DeepSeek V4-Pro 高峰输出从 6 元涨至 27 元/百万 token，涨幅 350%**；缓存命中输入从 0.025 元升至空闲时段 0.15 元、高峰时段 0.3 元，涨幅分别为 500% 和 1100%。官方把调价归因于「更合理地配置资源、提升服务稳定性」。

**按能力分层。** 海外这边，OpenAI 在 GPT-5.6 同代内搭了三层产品矩阵：旗舰 Sol 守价，Terra 降价，Luna 大幅降价——高端守价、中端巩固、低端抢量。Anthropic 的 Claude Sonnet 5 则是典型的「上市优惠价」：以 2/10 美元（输入/输出，每百万 token）introductory 价推出，**2026 年 9 月 1 日回到 3/15 美元**。

## 为什么能涨得起来

**第一，前期的价格是补贴价。** 有分析指出，2024 到 2025 年本质是市场教育阶段——用接近免费的价格让用户养成调用习惯，让开发者把 AI 嵌入工作流。到 2026 年这个任务基本完成，企业客户的问题从「要不要用」变成「用哪个、怎么用得稳」。行业也从「技术突破驱动」转向「商业化验证期」。

**第二，推理负载本身在变重。** 长上下文、深度推理和 Agent 任务显著增加推理负载，高峰算力供给仍然紧张。**一个聊天回答是几千 token；一个带工具调用、重试和推理轨迹的 Agent 工作流是几万到几十万 token。**

**第三，需求价格弹性低于预期。** 智谱一季度 API 定价较上年末提升 83%，调用量反而增长 400%。这说明企业级客户为确定性付费的意愿已经形成。

还有一个结构性原因：**中国模型走的是稀疏架构路线，本身已经把分母压得很低。** 一个 1.6 万亿总参数、每次只激活 490 亿参数的模型，每 token 的计算量本来就只有稠密模型的 1/3 到 1/4。瑞银的调研显示中国头部模型厂商的 API 业务仍能保持 20% 到 40% 的毛利率。

**换句话说是：涨价不是因为亏得撑不住，而是因为价格之前定得太低。**

## 一个反直觉的现象

涨价和总支出上升，可以同时发生。

公开的观察是：**每 token 价格在快速通缩，但总推理支出在几乎所有人身上都在上升。** 原因是乘数效应——

- **Agent 成倍放大 token 数。** 普通问答几千 token，Agent 工作流几万到几十万。
- **推理模式会计费「思考」。** 推理 token 是额外成本。
- **长上下文窗口鼓励滥用。** 百万 token 的窗口让人顺手把整个代码库塞进去，而一次检索只需要 2% 的量。
- **用量在复利。** 有数据称 OpenAI 的 API 每分钟处理超过 150 亿 token。

正确的心理模型是三行：**每个任务的 token 数 × 每月任务数 × 混合单价。** 只看账单的团队，往往在 Agent 项目超预算 5 倍之后，还不知道是哪一行变了。

## 几个可以往下看的问题

**第一，峰谷定价会不会成为行业惯例。** 它的本质是把数据中心的利用率问题转移给用户。DeepSeek 的两轮调整（先分峰谷、再取消周末峰谷）说明这个机制还在打磨。

**第二，缓存定价什么时候被真正理解。** 缓存命中输入涨价 500%–1100%，幅度远大于普通输入。这意味着**不命中缓存的代价在快速上升**，但对多数调用方来说，这套定价的复杂度本身就是一个成本。

**第三，按任务的定价会不会铺开。** 有厂商开始卖任务配额（如每 5 小时 300–1200 次 API 调用或 100–1000 条 prompt），海外也有明确的「按动作定价」趋势——付固定费用完成一件定义好的事，比如「从发票中提取数据」。这对非技术团队更友好，也让成本更好预测。

**第四，开源权重的对冲。** 有一句提醒很实在：开源模型的权重可以随时换，一旦调价幅度超出预期，把流量切到自托管或兼容 API 只是改个配置。**这种套利能力本身就是价格上限。**
